# الأمان — نموذج الحماية وقائمة النشر

هذا الملف يشرح كيف يحمي التطبيق بيانات الأطفال وأولياء الأمور، والخطوات المطلوبة عند النشر.

## 1. نموذج الحماية باختصار

| الطبقة | ما الذي تغيّر |
|---|---|
| **تسجيل الدخول** | يتم التحقق على الخادم فقط (`/api/auth/login`). الجهاز لا يقارن أي كلمة مرور. |
| **كلمات المرور** | تُحفظ في جدول `credentials` مشفّرة بـ bcrypt، ولا تُحفظ في بيانات الروضة ولا تُعاد للتطبيق ولا تُكتب في Firestore. |
| **الجلسات** | توكن موقّع (HMAC-SHA256) صالح 30 يوماً، يحمل الدور ومعرّف الروضة. يُحفظ في `SecureStore`. |
| **الصلاحيات** | كل مسارات `/api/*` تتحقق من التوكن والدور. ولي الأمر يرى طفله ورسائله فقط، والمعلمة لا ترى الوارد أو رواتب الزميلات، والضيف يرى البيانات العامة فقط. |
| **فصل الروضات** | البيانات في `school_state` مفصولة بـ `school_id` المأخوذ من التوكن، لا من الطلب. |
| **كلمات المرور المؤقتة** | أي دخول بكلمة افتراضية أو مؤقتة يُجبر على تغييرها، والتوكن المؤقت لا يفتح أي بيانات خاصة حتى التغيير. |
| **لوحة المطوّر** | تُفتح بتحقق على الخادم (`/api/auth/developer-unlock`) وتمنح توكناً مؤقتاً لساعتين. |
| **الحد من المحاولات** | 8 محاولات دخول خاطئة لكل حساب كل 15 دقيقة، و60 لكل عنوان IP. |
| **ترويسات أمان** | `nosniff` و`HSTS` و`X-Frame-Options`، ومنع رفع ملفات HTML/SVG/JS. |

### الترحيل التلقائي
عند أول تشغيل للخادم بعد التحديث:
1. تُنقل بيانات الجدول القديم `app_state` إلى `school_state` تحت الروضة الافتراضية `ahbabullah`.
2. تُستخرج أي كلمة مرور مخصّصة كانت محفوظة بنص واضح، وتُشفّر في `credentials`، وتُحذف من البيانات.
3. كلمات المرور الافتراضية القديمة (`1234` و`dev@2026`) لا تُنقل؛ تُقبل مرة واحدة فقط مع **إجبار التغيير**.

## 2. قائمة النشر (إلزامية)

1. **`SESSION_SECRET`**: سرّ عشوائي لا يقل عن 32 حرفاً. الخادم يرفض التشغيل في الإنتاج بدونه.
   ```bash
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```
2. **`FIREBASE_API_KEY` و`FIREBASE_PROJECT_ID`** على الخادم، لتفعيل دخول مدراء الروضات عبر Firebase.
3. **نشر قواعد Firestore الجديدة**:
   ```bash
   firebase deploy --only firestore:rules
   ```
4. **حساب مشغّل المنصة**: في Firebase Console أنشئ المستند `platformAdmins/<uid>`، حيث `<uid>` هو معرّف حساب Firebase الخاص بك. بدونه لا يمكن إنشاء روضات جديدة من لوحة المطوّر.
5. **أول دخول للمدير**: سجّل الدخول بـ `admin` وكلمة المرور القديمة أو قيمة `ADMIN_INITIAL_PASSWORD`، وسيُطلب منك تعيين كلمة مرور قوية فوراً.
6. **أول فتح للوحة المطوّر**: عيّن كلمة مرور مطوّر جديدة من قسم «الأمان وكلمات المرور»، أو اضبط `DEVELOPER_PASSWORD`.
7. **المعلمات وأولياء الأمور**: من شاشة الإدارة اضغط «إعادة تعيين كلمة المرور» لإنشاء كلمة مؤقتة لكل حساب وتسليمها له بشكل خاص. يستطيع المستخدم بعدها تفعيل حسابه من «إنشاء حساب جديد» أو بالدخول المباشر.

## 3. تنظيف مطلوب لمرة واحدة

- **Firestore**: إن كانت النسخ القديمة قد كتبت حقول `password` أو `parentPassword`، فستُحذف تلقائياً عند أول تعديل لكل سجل. لحذفها فوراً شغّل سكربت إداري، أو احذف الحقول من Console.
- **مفتاح Google Play**: كان مسار `/api/setup/google-play-key` العام يسمح لأي شخص باستبدال السر في GitHub. **أُزيل المسار**. يُنصح بتدوير `GITHUB_PAT` المستخدم سابقاً على الخادم، وبمراجعة قيمة `GOOGLE_PLAY_SERVICE_ACCOUNT_KEY`.
- **كلمات المرور القديمة**: كلمات المرور التي كانت محفوظة في التطبيق كانت قابلة للقراءة. يُنصح بإعادة تعيينها لجميع المستخدمين.

تغطي الاختبارات: الترحيل، ومنع القراءة والكتابة المجهولة، ورفض التوكن المزوّر، وإجبار تغيير كلمة المرور، وصلاحيات المعلمة وولي الأمر، ومنع انتحال الرسائل، والتفعيل بكلمة مؤقتة، ولوحة المطوّر، وفصل الروضات، والحد من المحاولات. تعمل تلقائياً في CI.
